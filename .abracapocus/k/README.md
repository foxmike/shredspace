# k

## Goal

Final validation and release verification on Linux. scripts/validate_plugin.sh: paste-and-run with zero editing and no placeholders; reconfigures and rebuilds all three Linux targets via cmake --preset linux-release and cmake --build, runs the complete unit-test suite through ctest with failure propagation, verifies VST3, LV2, and Standalone artifact existence with explicit per-artifact pass/fail output, and prints a final summary; no 'set -e'. tests/StateRoundTripTests.cpp: set non-default values across every APVTS group, select a non-default profile and scene, serialize processor state, construct a fresh processor, restore, and verify exact parameter, profile, and scene equality including the schema version. docs/verification/phase_k_release.md: records the executed command matrix (configure, build, full ctest, artifact checks) with results, and the explicit remaining operator work before release: real-guitar evaluation after high-gain amp or NAM processing covering alternate picking, economy picking, sweep arpeggios, legato, tapping, bends, wide vibrato, held notes, phrase endings, chords, palm-muted rhythms, sustained feedback, string noise, and gated silence, judged for dry attack clarity, repeated-note clutter, upper-mid buildup, pumping, width, mono compatibility, bloom timing, sustained-note size, and profile usefulness, at 44.1/48/96 kHz in REAPER, Studio One, Bitwig, and Standalone across VST3 and LV2; profile tuning updates to the bundled resources based on that evaluation; and the later Windows MSVC build via the Aural Maximizer Pro workflow. Profiles are not release-ready merely because the JSON parses.

## Notes

- Async: Wave 1: k.1 creates scripts/validate_plugin.sh alone. Wave 2: k.2 creates tests/StateRoundTripTests.cpp and registers it in CMakeLists.txt (k.2 depends on k.1). Final wave: k.3 executes the validation script and writes docs/verification/phase_k_release.md (k.3 depends on k.2).
- Risk: The state round-trip test is the release gate for spec stability: any parameter, profile, or scene state that fails exact restoration is a shipping blocker. The verification document must record real executed commands and results, never aspirational ones.
