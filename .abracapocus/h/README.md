# h

## Goal

Wire the adaptive engine into the audio path so analysis measurably changes the sound - the defining product behavior. Source/Analysis/AdaptiveSnapshot.h: fixed-size POD destination snapshot carrying contraction, bloom, mode, and per-voice wet dB delta, T60 octave delta, LPF octave delta, width delta, transient-softening delta, and diffusion delta; published through two preallocated buffers with atomic active index and generation counter using release semantics on write and acquire on read; no strings, no allocation, no destruction, no shared_ptr. DelayVoice consumes the snapshot each block, combining deltas with base values per the layering rules (dB addition for wet level; power-of-two octave scaling for T60 feeding the feedback calculation, then the 0.985 cap; power-of-two octave scaling for LPF; clamped linear addition for width to [0,2], softening to [0,1], diffusion to [0,0.40]), weighted by the voice's adaptiveRole, with per-destination smoothing driven by the contraction attack/release and bloom rise/hold/release parameters so adaptation never zippers; base APVTS values are never written by this path. PluginProcessor integrates the chain in processBlock at bounded control-rate cadence: feed the resampler from the pre-delay analysis tap, step analyzer, onset, density, sustain, and controller, publish the snapshot, and honor Off mode as a provably static path. tests/AdaptiveEndToEndTests.cpp: identical input renders measurably different output for DEFINITION 0% versus 100% on dense impulse-train input (wet level and effective tail contract); BLOOM 0% versus 100% on sustained input with a phrase gap (bloom increases, gaps reveal existing tail energy); Adaptive Mode Off versus Articulation; Off mode sample-identical to the static path within floating-point determinism; and macro, scene, and adaptive processing leave base destination APVTS values unchanged throughout.

## Notes

- Async: Wave 1: h.1 creates Source/Analysis/AdaptiveSnapshot.h alone. Wave 2: h.2 applies snapshot deltas inside DelayVoice.h/.cpp (h.2 depends on h.1). Wave 3: h.3 integrates resampler feed, analysis stepping, and snapshot publication into PluginProcessor.h/.cpp (h.3 depends on h.2). Final wave: h.4 creates tests/AdaptiveEndToEndTests.cpp and registers it in CMakeLists.txt (h.4 depends on h.3).
- Risk: This phase guarantees the analyzer is not an orphan subsystem. Overreaction reads as pumping: per-destination attack and release come from the Intelligence parameters, and a single shared smoothing envelope across destinations is forbidden.
