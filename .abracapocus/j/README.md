# j

## Goal

Implement the complete native JUCE GUI with four pages. Source/GUI/CustomLookAndFeel.h/.cpp: the visual identity implemented strictly against the LookAndFeel_V4 virtual signatures present in the vendored JUCE submodule on disk - in particular drawPopupMenuItem takes individual parameters (isSeparator, isActive, isHighlighted, isTicked, hasSubMenu, text, shortcutKeyText, icon, textColour), not a juce::PopupMenu::Item struct; every override verified against the actual vendored headers, never remembered API. Source/Telemetry/TelemetryState.h/.cpp: scalar latest-value telemetry as atomics (left/right peak, left/right RMS, activity, density, sustain, contraction, bloom, correlation, safety flag) plus a juce::AbstractFifo used only for detector time-series history where overflow is acceptable and never authoritative for current meter values; published from PluginProcessor with no locks or allocation on the audio side. Source/GUI/MeterComponent.h/.cpp: stereo output meters plus the activity, density, contraction, bloom, and safety indicator cluster reading TelemetryState on a GUI timer. Source/GUI/PerformancePage.h/.cpp: the eight macro controls, profile browser, four scene buttons, global Mix, input and output, bypass, tap tempo, Hold, adaptive mode, indicators, and meters. Source/GUI/VoicesPage.h/.cpp: complete Voice A and Voice B expert editing (enable, time ratio, fine offset, level, tail scale, adaptive role, pan, width, stereo offset, cross-feedback, HPF, LPF, Presence Guard, transient softening, modulation, drift, diffusion, saturation). Source/GUI/ToneMotionPage.h/.cpp: filter controls, Presence Guard controls, transient-softener controls, saturation, modulation rate and depth, drift, diffusion, stereo behavior, and the low-frequency mono crossover. Source/GUI/IntelligencePage.h/.cpp with Source/GUI/DetectorDisplay.h/.cpp: sensitivity, input gate, density window and thresholds, sustain thresholds, phrase-gap timing, contraction response, bloom response, and the adaptation destination amounts, with live onset/density/sustain/gap visualization fed from the telemetry history FIFO. Each page owns its own APVTS attachments; macro controls talk to the MacroEngine and never directly write coordinated destination parameters. PluginEditor assembles four-page navigation in a resizable layout. GUI code never runs on the audio thread and reads audio data only through TelemetryState.

## Notes

- Async: Wave 1: j.1 (CustomLookAndFeel) and j.2 (TelemetryState plus its publication from PluginProcessor.h/.cpp) run in parallel with disjoint files. Wave 2: j.3 (MeterComponent) depends on j.1 and j.2. Wave 3: j.4 (PerformancePage), j.5 (VoicesPage), j.6 (ToneMotionPage), and j.7 (IntelligencePage plus DetectorDisplay) run in parallel with disjoint files, all depending on j.3. Final wave: j.8 assembles PluginEditor.h/.cpp with four-page navigation and registers all GUI and Telemetry sources in CMakeLists.txt (j.8 depends on j.4, j.5, j.6, j.7). PluginProcessor.h/.cpp is owned only by j.2 and PluginEditor.h/.cpp plus CMakeLists.txt only by j.8 in this phase.
- Risk: The drawPopupMenuItem signature mismatch against the vendored JUCE revision is a known prior failure mode from Aural Maximizer Pro; overrides must be checked against the submodule headers on disk. Source/Telemetry is the thin layer keeping DSP and GUI independent; neither may include the other directly.
