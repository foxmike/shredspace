# b

## Goal

Implement the complete parameter system with stable IDs frozen in this phase. Source/Parameters/ParameterIDs.h: every automatable parameter ID as a constant, grouped GLOBAL_*, PERF_*, TIME_*, VOICE_A_*, VOICE_B_*, INTEL_*, STEREO_*, SCENE_*, plus a state schema version constant. Public performance parameters: input gain -24..+24 dB default 0, output gain -24..+24 dB default 0, Mix 0-100% default 22%, bypass Off default, bypass mode Hard/Trails default Trails, mix mode Insert/Send default Insert, adaptive mode Off/Level/Articulation default Articulation, routing Parallel/AtoB/BtoA default Parallel, tap (momentary), Hold momentary-or-latch default Momentary, spillover On, safety RMS limiter On, low-frequency mono On, LF mono crossover 60-500 Hz default 180 Hz, and the eight macros: TIME 20-2000 ms or sync division default 380 ms, SPACE 0-100% default 40%, DEFINITION 0-100% default 65%, BLOOM 0-100% default 45%, TAIL 0.15-12 s default 2.8 s, FOCUS 0-100% default 55%, WIDTH 0-100% default 65%, CHARACTER 0-100% default 30%, plus scene selection and scene morph. Expert per-voice parameters with Voice A / Voice B defaults respectively: enable On/On, time ratio 0.25-4.0 (0.5 / 1.0), fine offset -50..+50 ms (0/0), level -60..0 dB (-12 / -10), tail scale 0.25-4.0 (0.65 / 1.2), adaptive role 0-100% (40 / 85), pan -100..+100 (-20 / +20), width 0-200% (60 / 130), stereo offset 0-30 ms (3 / 11), cross-feedback 0-100% (15 / 35), modulation phase 0-180 deg (90 / 180), HPF 40-1500 Hz (180 / 220), LPF 2-20 kHz (6500 / 5500), presence frequency 1.5-6 kHz (3200 / 3200), presence guard 0-12 dB (4 / 5), attack softening 0-100% (30 / 40), modulation rate 0.05-5 Hz (0.35 / 0.23), modulation depth 0-8 ms (0.4 / 0.7), drift 0-100% (10 / 15), diffusion 0-40% (8 / 12), saturation 0-100% (8 / 10). Expert intelligence parameters: sensitivity 0-100% default 55, input gate -80..-20 dB default -55, density window 200-1000 ms default 500, density start 1-8 ev/s default 3, density full 6-20 ev/s default 12, sustain start 50-800 ms default 180, sustain full 150-2000 ms default 650, phrase gap 20-500 ms default 120; contraction attack 1-100 ms default 8, contraction release 20-1000 ms default 220, wet reduction 0-18 dB default 8, tail reduction 0-2 oct default 1, tone darkening 0-2 oct default 0.75, width reduction 0-100% default 35, attack softening increase 0-100% default 45; bloom rise 20-1500 ms default 220, bloom hold 0-2000 ms default 350, bloom release 50-3000 ms default 800, wet lift 0-12 dB default 4, tail expansion 0-2 oct default 0.75, tone opening 0-1 oct default 0.35, width expansion 0-100% default 30, diffusion increase 0-30% default 12; transient-softener crossover 1000-6000 Hz default 2500; routing cascade amount; glide 5-1000 ms; time mode Milliseconds/HostSync/Tap with sync divisions Whole through Sixteenth plus dotted (x1.5) and triplet (x2/3). Internal state that must never appear in APVTS: detector running means and deviations, FFT history, onset timestamps, runtime activity/density/sustain/phrase-gap values, macro destination tables, scene names, profile names/descriptions/tags, migration metadata, telemetry values, safety intervention state, delay-buffer contents, resampler state. Source/Parameters/ParameterLayout.h/.cpp builds the full APVTS layout from these definitions, constructed across three serialized tasks by parameter group. Source/Parameters/ParameterSnapshot.h/.cpp provides the per-block real-time-safe value snapshot with domain-correct smoothing exactly per the purpose rules (linear for dB/pan/width/signed/normalized with dB-to-linear conversion after smoothing at the stated initial times; multiplicative only for strictly positive frequency/T60/rate; delay time excluded entirely because Smooth/Bend owns it). PluginProcessor gains APVTS ownership, getStateInformation/setStateInformation via the ValueTree with the schema version, and prepareToPlay allocation of the snapshot. tests/TestMain.cpp is the juce::UnitTest console runner registered as a CTest target; tests/ParameterTests.cpp verifies every ID exists in the layout, ranges and defaults match the values above, internal-state names are absent from APVTS, and state round-trips through get/setStateInformation exactly.

## Notes

- Async: Wave 1: b.1 creates ParameterIDs.h alone. Wave 2: b.2 creates ParameterLayout.h/.cpp containing the global, performance-macro, timing, stereo, and scene groups (b.2 depends on b.1). Wave 3: b.3 extends ParameterLayout.cpp with the complete Voice A and Voice B expert groups (b.3 depends on b.2, serialized same-file write). Wave 4: b.4 extends ParameterLayout.cpp with the intelligence detector, contraction, and bloom groups (b.4 depends on b.3, serialized same-file write). Wave 5: b.5 creates ParameterSnapshot.h/.cpp (b.5 depends on b.4). Wave 6: b.6 wires APVTS ownership, state save/restore, and snapshot allocation into PluginProcessor.h/.cpp and registers Parameters sources in CMakeLists.txt (b.6 depends on b.5). Final wave: b.7 creates tests/TestMain.cpp and tests/ParameterTests.cpp and adds the test-runner CTest target to CMakeLists.txt (b.7 depends on b.6, serializing the CMakeLists.txt write).
- Risk: Parameter IDs freeze permanently in b.1; every range and default must be transcribed exactly as stated in the goal, never invented, because changing IDs after release breaks automation and recall. Per-task focused verification is compile-only cmake builds of touched targets; ctest execution belongs to phase verification so backends do not retry-loop against test files created in the same task.
