# a

## Goal

Establish the buildable plugin scaffold with exact product identity and all target formats. Source/PluginProcessor.h/.cpp: minimal AudioProcessor shell whose isBusesLayoutSupported accepts exactly mono-in/mono-out, mono-in/stereo-out, and stereo-in/stereo-out; processBlock clears every output channel beyond the input channel count deterministically before any processing so no uninitialized channel can reach the host; prepareToPlay/releaseResources stubs ready for later allocation; juce::ScopedNoDenormals at the top of processBlock from the start. Source/PluginEditor.h/.cpp: minimal resizable editor connected to the processor. CMakeLists.txt: juce_add_plugin with PRODUCT_NAME ShredSpace, COMPANY_NAME 'nSpace Systems', VERSION 1.0.0, PLUGIN_MANUFACTURER_CODE NSPC, PLUGIN_CODE ShSp, BUNDLE_ID com.nspacesystems.shredspace, LV2URI urn:nspacesystems:plugin:shredspace, FORMATS VST3 LV2 Standalone, CXX_STANDARD 20, consuming the existing ./JUCE submodule via add_subdirectory without touching it. CMakePresets.json: linux-release (Release, build directory build/linux-release) and windows-msvc (configuration only, not built in this plan). scripts/build_all.sh: paste-and-run with zero editing and no placeholders, configures with cmake --preset linux-release, builds all three Linux targets, and checks that the VST3, LV2, and Standalone artifacts exist, printing explicit pass/fail per artifact; no 'set -e'. .gitignore covers build directories and IDE state. Verification throughout this phase is explicit: cmake --preset linux-release, cmake --build build/linux-release, artifact existence checks. The phase verification artifact docs/verification/phase_a_scaffold.md records the exact commands executed and results.

## Notes

- Async: Wave 1: a.1 creates Source/PluginProcessor.h/.cpp alone. Wave 2: a.2 creates Source/PluginEditor.h/.cpp, which includes the processor header (a.2 depends on a.1). Wave 3: a.3 creates CMakeLists.txt and CMakePresets.json referencing the four shell sources (a.3 depends on a.2). Wave 4: a.4 creates scripts/build_all.sh and .gitignore (a.4 depends on a.3). Final wave: a.5 writes docs/verification/phase_a_scaffold.md recording executed commands (a.5 depends on a.4).
- Risk: CMakeLists.txt and CMakePresets.json are single-owner (a.3) this phase. The bus-layout contract and deterministic output-channel initialization land in a.1 because retrofitting layouts later breaks host behavior. Identity codes NSPC/ShSp and the LV2 URI are frozen here; changing them later breaks user sessions.
