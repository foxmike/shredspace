# i

## Goal

Implement profiles, macros, and scenes with their tests. Source/Profiles/ProfileSchema.h/.cpp: profile format with schema_version, product_version, profile_name, author, description, base_parameter_values, macro_mapping, scene_values, tags; validation requiring every referenced parameter ID to exist, unknown IDs handled by a defined migration rule, schema version checked, malformed profiles failing safely and never reaching the audio thread. Source/Profiles/ProfileManager.h/.cpp: loads bundled profiles from embedded binary data and user profiles from disk with all parsing and file IO strictly off the audio thread; profile recall is an explicit preset action that may replace base APVTS values on the message thread only. Source/Profiles/ProfileSnapshot.h/.cpp: real-time handoff as two preallocated fixed-size POD numeric snapshots with atomic active-index and generation under release/acquire semantics; the audio thread never sees strings, tags, or filenames and never allocates or destroys; std::atomic<std::shared_ptr> is forbidden. Source/Parameters/MacroEngine.h/.cpp: the eight macros (TIME, SPACE, DEFINITION, BLOOM, TAIL, FOCUS, WIDTH, CHARACTER) map to profile-supplied destination tables; for normalized macro value u in [0,1], each destination delta = delta_min + u_curved*(delta_max - delta_min) with u_curved = u^curve, curve > 0, default 1.0; deltas combine into effective values per the layering rules and never call setValueNotifyingHost or rewrite destination APVTS values; macro coordination follows the plan: SPACE coordinates voice levels, wet prominence, diffusion, and bloom availability; DEFINITION coordinates contraction strength destinations; BLOOM coordinates bloom strength destinations; FOCUS coordinates HPF, LPF, guard, and softening; WIDTH coordinates pan, width, offset, cross-feedback, modulation phase, and LF mono; CHARACTER coordinates saturation, modulation depth, drift, diffusion, attack softness, and bandwidth; TIME drives the DelayTimeController; TAIL sets nominal T60. Source/Profiles/SceneManager.h/.cpp: four scenes per profile (A Tight, B Open, C Bloom, D Special) storing the eight macro targets, Mix target, routing target, and Hold behavior; continuous values morph as delta_scene = scene_target - base_value applied internally without overwriting base macro APVTS values; linear morphing p = (1-lambda)*p_A + lambda*p_B for linear values; logarithmic morphing p = p_A*(p_B/p_A)^lambda only when both endpoints are strictly positive (frequency, time, T60, rate); discrete values (routing) switch under the wet-path crossfade, never numerically interpolated; delay-time changes route through Smooth/Bend; spillover preserves tails during scene changes. Twelve bundled profiles as JSON resources embedded via juce_add_binary_data with engineering starting values consistent with every parameter range: Precision Rack, Rapid Definition, Neoclassical Flight, Wide Arpeggio, Singing Lead, Dry Center Arena, Legato Space, Dark High-Gain, Ballad Bloom, Controlled Cascade, Mono Rig Polish, Buffer Bend; profile descriptions use behavior language only, and no artist or song name appears anywhere. tests/ProfileMacroSceneTests.cpp: all bundled profiles parse; every referenced ID exists; schema version checked; malformed profiles fail safely; unknown IDs follow the migration rule; loading performs no audio-thread IO; no artist or song names in shipped resources; every macro destination remains in range across the full macro sweep; macro movement does not rewrite destination APVTS values; curves and min/max mappings behave correctly; linear values morph linearly and positive time/frequency values logarithmically; discrete parameters switch under the crossfade; base macro values remain unchanged through scene morphs.

## Notes

- Async: Wave 1: i.1 (ProfileSchema) and i.4 (MacroEngine, depending only on the frozen phase-b parameter system) run in parallel with disjoint files. Wave 2: i.2 (ProfileManager) depends on i.1. Wave 3: i.3 (ProfileSnapshot handoff) and i.5 (SceneManager) run in parallel with disjoint files, both depending on i.2 and i.4. Wave 4: i.6 creates the twelve Resources/Profiles JSON files and adds Profiles and MacroEngine sources plus juce_add_binary_data to CMakeLists.txt (i.6 depends on i.3, i.5). Final wave: i.7 creates tests/ProfileMacroSceneTests.cpp and registers it in CMakeLists.txt (i.7 depends on i.6). CMakeLists.txt has serialized sequential owners i.6 then i.7.
- Risk: The macros-never-rewrite-base-APVTS rule is this phase's central contract; an implementation writing macros through setValueNotifyingHost is wrong even if it sounds identical, because it breaks automation, undo, and recall. Profile numeric values are engineering starting points; real-guitar tuning is explicit operator work before release.
